# プレイログと感想から課題を検討する

NYORO-RIN で遊んだ人のプレイログ（DESIGN.md 20.1）と感想（20.2）を読み、直す候補の一覧を作る。
**読むだけで、データとコードは変えない。** 直すか、issue にするかはユーザーが決める。

## 1. 読む環境を決める

- `--env local`（既定）はローカルの D1。承認なしで読んでよい
- **`--env dev` と `--env production` はリモートの D1 を読む。実行する前にユーザーの承認を取る**
  （AGENTS.md「プレイログと感想」）。どちらを読むか、何日分（`--days`、既定 30）かも確かめる
- wrangler の認証が切れていたら、ユーザーに `! npx wrangler login` を頼む

## 2. 集計を読む

次を順に実行し、出力を読む。どれも SELECT だけで、書き込みはしない。

```sh
npm run stats -- summary  --env <env> --days <N>
npm run stats -- stuck    --env <env> --days <N>
npm run stats -- hints    --env <env> --days <N>
npm run stats -- abandon  --env <env> --days <N>
npm run stats -- feedback --env <env> --days <N> --limit 50
```

| 集計       | 分かること                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------- |
| `summary`  | 難易度ごとの試行、クリア、放棄率、クリア時間、ヒントやアシストなしで解けた割合。版ごとのログ数 |
| `stuck`    | 60 秒以上手が止まった盤面で、次の一手に要った定石。止まった後にヒントを見たか、やめたか        |
| `hints`    | ヒントで示した内容（定石の ID、`MISTAKE`、`REVEAL`）の内訳                                     |
| `abandon`  | 放棄した盤面の進み具合と、そこで次に要った定石                                                 |
| `feedback` | 感想の本文と、送ったときの盤面の様子                                                           |

気になる試行は `npm run stats -- log <playId> --env <env>` で時系列を見る（`playId` は、`feedback` の
出力で盤面がある感想の行に出る）。

## 3. 課題の候補を考える

数字を DESIGN.md の意図と突き合わせる。見る観点の例:

- **難易度の分け方**（13.2、13.7）: 初級の放棄率やクリア時間が中級と変わらない、初級で `TRIAL` に詰まっている、など
- **定石の教え方**（第 11 章、12.3）: 特定の定石で止まる時間が長い、その定石のヒントを段階 3 まで進める人が多い。ヒントの文面や図、ガイドで扱う定石の範囲の候補になる
- **誤りの扱い**（11.3）: `stuck` や `hints` に `MISTAKE` が多い。矛盾の表示や自動 × の段階の候補になる
- **操作**（第 7 章）: 元に戻すやリセットが多い、ズームの回数が多い（`log` で個別に見る）
- 感想（`feedback`）では、同じ要望や不具合が複数の人から来ているかを見る。人は ID の先頭 8 文字で区別する

件数が少ないうちは割合で語らない。何件のうち何件かを書き、偶然で説明できる差は候補に入れない。

## 4. ユーザーに報告する

次の形でまとめる。根拠の数字は、どの集計の、どの行かが分かるように書く。

| 候補         | 根拠                                          | 影響                               | 直し方の案                       | 確かさ                         |
| ------------ | --------------------------------------------- | ---------------------------------- | -------------------------------- | ------------------------------ |
| <何が問題か> | <集計名と数字（n 件中 m 件など）、感想の要約> | <どの難易度・どの場面の人が困るか> | <DESIGN.md のどこをどう変えるか> | 高 / 中 / 低（件数が少ない等） |

- 未決事項（DESIGN.md 第 23 章）に関わる候補は、そう明記する
- **issue は勝手に作らない。** ユーザーが選んだ候補だけ、承認を得てから `gh issue create` で作る

## プライバシーの決まり

- **この repo は公開している。** issue、コミット、PR に、感想の本文をそのまま貼らない。要約し、個人を
  特定できる内容（名前、連絡先、端末の詳細など）は落とす
- ID の先頭 8 文字や `playId` も issue に書かない。手元での報告にだけ使う
- 集計の出力をファイルに保存するときは scratchpad に置き、repo に入れない
